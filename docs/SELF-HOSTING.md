# Self-hosting the compiler

Status: **planned** (plan.md T35–T40). Nothing here is built yet; this page is the design the
cards implement and is updated by each of them.

## How V does it (the model)

- The V compiler is written in V (`vlang/v`, `cmd/v`, `vlib/v`). Its main backend emits C and
  calls a C compiler (`-cc`, default system `cc`/`clang`/`gcc`; a prebuilt `tcc` from
  `vlang/tccbin` is used on some platforms for fast debug builds).
- `vlang/vc` holds `v.c`: the whole compiler translated to one C file, regenerated by CI from
  `vlang/v` on every commit.
- `make` (`GNUmakefile` / `make.bat`) clones `vc`, runs `cc -o v1 vc/v.c`, then `v1` builds
  `v2` from `cmd/v`, then `v2` builds the final `v`. No V binary is needed to start.
- `v self` rebuilds the running compiler from its own source; `v up` pulls and does the same.

Sources: <https://github.com/vlang/v> (README "Installing V from source", `GNUmakefile`,
`cmd/tools/vself.v`), <https://github.com/vlang/vc>, <https://docs.vlang.io>.

## How it maps to Stator

| V | Stator (planned) | Card |
| --- | --- | --- |
| compiler written in V | `packages/compiler` in the admitted TS subset | T35 |
| `vlang/vc` `v.c` | generated C snapshot of `statorc` + runtime | T36 |
| `cc v.c -> v1 -> v2 -> v` | stage0 -> stage1 -> stage2, byte-identical C | T37 |
| `v self` | `stator self` | T37 |
| `-cc`, system cc, tcc | `--cc` / `STATOR_CC` / `CC`, clang/cc/gcc | T38 |
| CI regenerates `vc` | CI job `bootstrap` | T39 |

Today: `statorc` is TypeScript running on Node and emits C, then calls `clang`
(`packages/compiler/src/cli/build.ts`). `pnpm run test:selfhost` only *explains* the compiler
with itself; it is `not-yet` (STA1214 ×1887).

## Enable / disable

Not available yet. When built: the Node-hosted compiler stays the default; the bootstrap path is
opt-in via `pnpm run bootstrap:stages` and `stator self`; the CI job is skipped until T35 lands
(flag in `packages/tests/selfhost/targets.json`).

## Test

- Now: `pnpm run test:selfhost` (ratchet on the compiler's diagnostic counts).
- Planned: `pnpm run bootstrap:stages` (fixed-point SHA-256 of stage1/stage2 C), goldens with
  the stage2 binary, `STATOR_CC=gcc` goldens.

## Limitations

- The compiler depends on Node and the TypeScript/tsgo program APIs; T35 must replace or wrap
  them, and some may stay host-only.
- The runtime links Boehm GC (`libgc`); the snapshot must document or vendor it.
- No bundled tcc; Windows is out of scope (plan.md §1).
